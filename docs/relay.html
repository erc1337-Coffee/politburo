Relay

Stores and forwards messages between the orchestrator and its workers. The only public part of the system. It checks tokens and decides nothing.

Package
packages/relay · @remilia/politburo-relay, no runtime dependency
Runs
Public host behind a TLS proxy. Image: node src/cli.ts serve --database /data/relay.sqlite --host 0.0.0.0
Reads
RELAY_VERIFICATION_KEY (Ed25519 public key, PEM), PORT (8790)
Stores
One SQLite file. A message expires 24 h after its sender's token; expired rows are deleted every 60 s.
Commands
keygen --directory, token, serve

One channel per attempt

A channel has two append-only directions with their own sequence numbers: commands from the orchestrator to the worker, telemetry from the worker to the orchestrator. Receivers follow an SSE stream and resume with Last-Event-ID; there is no acknowledgement route.

Errors: 400 invalid_json, 400 invalid_last_event_id, 401 unauthorized (missing, forged, expired or other channel: one answer for all), 403 forbidden (wrong role for the direction), 413 message_too_large, 429 too_many_requests. Channel names: [A-Za-z0-9_-]{1,100}.

Tokens

  • Format: base64url(claims).base64url(Ed25519 signature). Claims: {v: 1, channel, role, iat, exp}.
  • The orchestrator holds the signing key (/orchestrator/keys/relay_signing_key.pem); the relay holds only the public key. The relay can check a token but cannot make one.
  • Accepted clock skew for iat: 60 s.
  • Worker tokens live 3600 s. The orchestrator sends renew with a new one at half life. The worker stops itself 120 s before expiry without a renewal.
  • relay keygen writes the key pair. The orchestrator container makes it on first start and prints the public key for RELAY_VERIFICATION_KEY.

What the relay can read

Every message body is stored as JSON text: briefs, instructions, answers, progress, results and git bundles. The relay does not validate the message schema; the orchestrator and the worker do. The one exception is credentials.

A restarted worker makes a new key, so the orchestrator seals again. Variables: CLAUDE_CODE_OAUTH_TOKEN for claude-cli routes, <PROVIDER>_API_KEY for others, only those set in the orchestrator's environment.

Messages

Envelope: {v: 1, id, type, task, channel, sent_at, data}. The id is unique; a retried POST reuses it and receivers drop duplicates. Schemas are closed: unknown fields, wrong types and oversized texts are refused by the receiver.
