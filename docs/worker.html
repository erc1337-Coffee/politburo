Worker

A client that runs one attempt inside a Claude cloud session. It reads relay commands, runs Pi on the task, and sends progress, results and the commits as a git bundle. It holds no GitHub credential and never pushes.

Commands

CommandAction
startSets the heartbeat interval, prepares the worktree, runs round 1. A second start is ignored with a warning.
credentialsOpens the sealed variables. Logs only their names; the next heartbeat has no public key.
instructRuns the next round with the text as the whole prompt, or queues it while a round runs.
answerWrites the answer file that the ask_orchestrator tool waits for.
renewReplaces the token when the new one expires later, saves it and reconnects.
stopSafe stop: stops Pi; with send_bundle and a running round, commits and sends a final result.

Events at or below the saved sequence are skipped. Invalid commands and commands for another channel become warnings. The last 500 command ids are kept, so none runs twice.

Pi

pi -p --mode json --session-dir ~/.politburo_worker/<channel>/pi_session \
   --session-id task-<N>-attempt-<K> --model <start.model.pi_model> \
   --thinking ${PI_THINKING:-medium} --extension <route extension> --extension <ask_orchestrator> -- <prompt>
  • Environment: the session environment without CLAUDE_* and CCR_*, plus the opened credentials and PI_FALLBACK_TIERS (the start command's routes).
  • Limits: Pi is ended at max_seconds (2400) or after idle_seconds (180) with no output and no change in the worktree. Idle time does not count while a question waits.
  • Exit reason: completed for exit 0 without an error reply, else failed; or timeout, idle, stopped.
  • Summary: Pi's last reply.

Route extension

pi-support/codex-cursor-fallback.ts registers the virtual model fallback/codex-cursor. A route is tried only when its model is known to Pi, has auth, is not cooling down and was not tried for this request. On HTTP 401, 403 or 429, an auth, quota or rate-limit error, or 90 s of stream silence, the provider cools down for 30 minutes and the next route is tried.

Questions

The ask_orchestrator tool lets Pi ask the task owner when it cannot continue without a decision. The question goes to the task thread; the first reply of a person comes back. After question_wait_seconds (3600) Pi is told to stop and report what is done.

Round end

  1. Checks from start run with bash -lc in the worktree, each with its timeout; the last 2,000 characters of output are kept.
  2. git add --all and a commit Task N round R when something changed.
  3. Bundle of claude/task-N ^base with its SHA-256, sent in parts of 48,000 base64 characters. More than 64 parts (about 2.3 MB) is not sent and is reported as truncated.
  4. result with exit reason, summary, head and base commit, bundle digest, diff stat, checks, models with tokens and cost.

Restart

The session agent restarts the client once after exit code 5. The client resumes from ~/.politburo_worker/<channel>/: the command cursor, the unsent telemetry, the token with the latest expiry and start.json. A saved round runs again with the task prompt. The new process makes a new key, so the orchestrator seals the credentials again.
